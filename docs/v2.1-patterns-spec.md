# FW Paint v2.1 — Patterns + Face Perpendicular Spec

Status: **DRAFT — awaiting review**. Two features on top of the v2 palette system:
**Patterns** (a second kind of palette item: a hand-drawn 2D block grid placed as a plane) and
the **Face Perpendicular** placement mode (1-block-wide runs snapped to 45°).

---

## 1. Patterns — overview

A pattern is a W×H grid of cells (each a block or empty) drawn by hand in a new **pattern
editor**, saved in the same palette list as gradients, activated/cycled the same way, and
painted through the existing placement modes. Placement lays the pattern into a **2D plane**
oriented from the player's facing (snapped to 45°), starting at the pattern's **start** edge,
with tiling toggles controlling repetition — and a cache so adjacent strokes continue the same
pattern instead of restarting it.

## 2. Palette tab changes

- A second button at the top of the list: **[+ New]** **[+ Pattern]** **[Use] [Edit] [Delete]**
  — "+ Pattern" opens the pattern editor blank; Edit opens whichever editor matches the item's
  kind.
- The list now holds both kinds. Pattern rows show the name + a small thumbnail of the grid
  (instead of segment sprites); the expanded summary shows size (e.g. "12×8"), the tiling mode,
  the variation setting, and missing blocks exactly like gradients (red border etc.).
- **Use** activates the item as its kind's active (gradient vs pattern — see §5). The **B
  keybind** cycles only the kind matching the current paint type. The HUD row shows a pattern's
  thumbnail + name while Pattern paint is active.

## 3. The pattern editor

Its own screen like the gradient editor (same title bar/name row/Save/Cancel/unsaved-confirm
rules, same page scroll). Layout, top to bottom:

### 3.1 Preview (top, spans both columns)

- An **isometric preview** of the pattern as placed blocks, centred, on its own row.
- **Dynamic cell scale**: the preview targets a roughly constant on-screen size — sprites
  shrink as the grid grows, so a 32×32 pattern previews at the same footprint as a 4×4.
  (Same expandable ⛶ treatment as the gradient editor's previews.)

### 3.2 Left column — block list

- The same colour-sorted source list as the gradient editor (Source toggle above it).
- **Left-click a block to select it as the drawing block** — the block's sprite then
  **follows the cursor** while over the editor, so you always know what you're drawing with.
  (No primary/secondary slots — one selected block.)
- Under the block list: the **tiling toggle** —
  `Tile: none | sides | start/end | start/end + sides`.

### 3.3 Right column — the canvas (wider; there is no middle column)

- At the top, side by side: **Width** and **Height** number inputs (1–32 each). The canvas
  below re-sizes to W×H cells. Cells are small at 32×32 — the canvas targets a fixed overall
  footprint. *(Shrinking W/H crops cells outside the new size; growing adds empty cells —
  see Open Questions.)*
- The word **start** in small text centred **above** the grid, **end** centred **below** it —
  placement always begins at the start edge and advances toward end.
- **Drawing** (hold left mouse and scrub):
  - Mouse-down on an **empty cell or a cell holding a different block** → **draw mode**: every
    cell the drag touches is set to the selected block (over empty, same, or different cells
    alike).
  - Mouse-down on a cell **already holding the selected block** → **erase mode** for that drag:
    cells holding that same block are cleared; other blocks and empty cells are untouched.
  - Scrubbing never toggles — a drag is either all-draw or all-erase, decided at mouse-down.
- Empty cells are **holes**: placement skips them (whatever is there stays).

## 4. Data model

Patterns live in the same `fw-paint-palettes.json` list so ordering/cycling stays unified.
Items gain a `kind` discriminator (absent = `GRADIENT` for existing saves):

```jsonc
{
  "id": "brick-arrow",
  "kind": "PATTERN",
  "name": "Brick arrow",
  "source": "HOTBAR_AND_INVENTORY",
  "width": 6,
  "height": 4,
  "cells": ["minecraft:bricks", "", "minecraft:stone", ...],  // row-major, start row first; "" = hole
  "tiling": "SIDES",         // NONE | SIDES | START_END | START_END_SIDES
  "patternVariation": 0      // 0 = off, 1-3 = Oklab-neighbour distance (§5.0)
}
```

The store gains a second active pointer: `activePattern` alongside `activePalette`.

Gradient-only fields (segments, stops, curve, sliders, noise settings) don't exist on patterns;
pattern fields don't exist on gradients. Missing-block logic reuses `missingBlocks()` over the
distinct cell blocks; the global Missing blocks policy applies the same way.

## 5. Placing a pattern

**Pattern is its own paint type**: V (and the Paint tab) now cycles
**Gradient → Noise → Solid → Pattern**. The palette-cycle keybind (B) is **filtered by the
current paint type** — in Gradient/Noise paint it cycles only gradient palettes, in Pattern
paint only patterns. There are **two active pointers** (`activePalette` for gradients,
`activePattern` for patterns) so switching paint type never loses the other selection; the HUD
and Paint tab show whichever matches the current paint type, and saving in an editor activates
its own kind. Pattern paint with no patterns saved shows the usual "press K to set one up"
guidance.

### 5.0 Pattern variation (experimental — patterns only for now)

No Chaos for patterns — they place what you drew. Variation gets a **new, simpler model** to
trial (gradients keep their existing model unchanged for now):

- The source blocks are ordered by **Oklab** (the same colour ordering the lists use).
- A per-pattern setting **Variation: Off | ±1 | ±2 | ±3** — when placing a cell, the block may
  be swapped for a uniformly-random pick among the blocks within N positions of it (either
  direction, the cell's own block included) in that ordering.
- Deterministic drawing at Off; gentle neighbour-colour shimmer at ±1…±3.

### 5.1 The pattern plane and axes

- At press time the **pattern plane** is fixed: it contains the clicked face's normal
  (the extrusion direction) and a horizontal **width axis** chosen from the player's facing,
  **snapped to the configured increment** (§7): the width axis is the horizontal direction
  perpendicular to the player's snapped facing, so the plane "faces" the player. 45° snapping
  means diagonal planes are possible.
- Mapping: the pattern's **height axis (start→end) runs along the extrusion direction** — the
  start row is the first block placed out of the clicked face (exactly where a gradient's t=0
  is). The **width axis** runs across the plane; the clicked column is width cell 0, cells run
  both ways along the width axis. A cell's block is `cells[u, v]` (u = signed distance along
  the width axis, v = steps out of the face).
- **Off-plane extrusion** ("the streak"): positions displaced along the plane's normal reuse
  the plane's nearest column — so a cube painted with one pattern shows the pattern on the
  faces parallel to the plane and edge-streaks on the perpendicular sides, as described.

### 5.2 Tiling

- `sides` → u wraps modulo W; without it, cells outside 0…W−1 place nothing.
- `start/end` → v wraps modulo H (columns keep going as long as the mode/markers let them);
  without it, a column stops after H cells (its pattern is complete).
- `start/end + sides` → both.

### 5.3 The pattern cache — continuing instead of restarting

Extends `GradientCaches` (same fingerprint/idle rules, keyed by the active item's content):
every placed cell records **(pattern id, u, v, plane origin + orientation)**.

A new press **continues** an existing cached pattern instead of starting fresh when:

- the clicked column sits on (or intersects) the **same extrusion plane** as a cached
  placement, or
- it is the neighbouring row/column of a cached placement **and the tiling setting allows
  growth in that direction** (sides for u-neighbours, start/end for v-continuation).

Then u/v are derived from the cached plane's coordinate system, so the drawing lines up.
Otherwise the press starts a new pattern at the clicked block (u=0, v=0) with a fresh plane
from the current facing. Works with Single, Face, Face Perpendicular, and 3D Fill (3D: v still
runs along cells' distance from the seed along the extrusion axis; u/normal from the plane).

## 6. New placement mode — Face Perpendicular

Cycle order becomes: Marker modes → **Single → Face → Face Perp → 3D Fill** → Disabled.

- Like Face, but instead of flooding the whole connected plane, it selects a **1-block-wide
  run** of face-exposed blocks: the line through the clicked block, lying in the clicked
  plane, running along the player's facing **snapped to the configured increment** — so 45°
  diagonal runs (stair-stepped) are possible. The run extends both ways from the clicked block
  while blocks stay connected/exposed/reachable.
- Constrained by markers exactly like Face: end markers stop columns; **inside markers only
  the marked blocks along the run are selected** (never the whole marker plane).
- Works with every paint: Solid, Gradient (incl. patterns), Noise.
- The green face-preview shows the run before clicking, like Face does.

## 7. Global setting — perpendicular snap

A Settings toggle: **"Perp snap: 45° | 90°"** — the angular snapping used both for the pattern
plane's width axis (§5.1) and Face Perpendicular's run direction (§6). Default 45°.

## 8. HUD

Unchanged except: an active pattern shows its thumbnail + name in the palette row, and the
sourcing line says "Pattern: <name>" while aiming.
